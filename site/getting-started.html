Getting started

From first sign-in to running work against your own repositories. Ten minutes, no local installation required — everything here happens in the dashboard.

  1. Sign in

    Open the DevAI dashboard and sign in with your Google account. Sign-in is handled by the platform's identity service; DevAI never sees your password. Your session lives in a secure, browser-only cookie, and everything you create — sandboxes, evaluation runs, connections, traces — is owned by your account and visible only to you.

  2. Complete your profile

    Go to Settings → Profile to review your display name and details. These appear wherever the platform attributes work to you: run history, published agents, audit records. You can update them at any time.

  3. Connect a model

    In Settings → Connections, add a connector for the model provider you want your agents to use. Paste the key once; it is stored in the platform's secret manager and never shown again, never written into files, and never placed inside a sandbox. Every model call is routed through the platform gateway and billed to your connection.

  4. Connect your GitHub

    In Settings → Source Control, connect the GitHub account or organization you want to develop against. Two ways in:

    MethodGood forWhat you provide
    Personal access tokenIndividuals and small teams; fastest setupA fine-grained token with repository read/write. Optionally set an Organization to scope listings and repository creation.
    GitHub AppOrganizations that want installation-scoped, revocable accessApp ID, installation ID, and the app's private key.

    Tokens and keys go straight into the platform's secret manager — the same vault that holds model keys. The dashboard only ever shows that a secret is set, never its value, and you can rotate or remove it whenever you like.

  5. Work with your repositories

    Open the Repos page. It now lists the repositories your connection can see — your organization if you set one, otherwise everything your token or app installation has access to. From here you can onboard existing repositories, create new ones in your organization, and scaffold projects. Pipeline runs and the chat assistant use the same connection, so the whole develop → review → release loop happens against your GitHub.

    If you open Repos before connecting, you'll see a short setup prompt pointing you back to Settings — nothing breaks, you're just not connected yet.

  6. Build your first agent

    With a model and source control connected, follow the build-agents guide: author a small manifest, run it in an isolated sandbox, evaluate it against a versioned dataset, and publish it once it passes the gate.

Who sees what

ThingScope
Your sandboxes, traces, evaluation runsOwned by you. Other users cannot see or reuse them, and the publication gate refuses evidence owned by anyone else.
Your repository listingsCome from your own connection. What you can see and create is exactly what your token or app installation allows.
Repositories you onboardListed for you. You won't see other tenants' onboarded repositories, and they won't see yours.
The platform's own GitHub organizationReserved for platform operators. Regular accounts always work through their own connection.

Feedback

The Feedback button in the dashboard files your report directly with the platform's owners, regardless of which GitHub you have connected. That channel is intentionally fixed: your product feedback always reaches the people who run the platform, and it never touches your repositories.

Frequently asked

Can DevAI read my secrets back to me?

No. Secret values are write-only from the dashboard's point of view. Once stored, the interface confirms a secret exists and lets you replace or delete it — it never displays the value.

What happens if I remove my GitHub connection?

Repository listing and creation stop working for your account until you connect again. Nothing is deleted: repositories you onboarded and runs you completed keep their history.

Do I need the CLI?

No. The dashboard covers the full loop. The CLI (devai adk …) drives the same authenticated interfaces and is there when you prefer a terminal or want to script things — see Build Agents.
